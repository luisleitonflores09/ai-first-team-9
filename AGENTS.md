# Project agent guidance

- The objective, scope, contract, and acceptance cases live under `docs/`; read the relevant files before changing behavior.
- Keep the demo in English, grounded in the fictional `knowledge/` documents, and include source links. Follow-up questions use the current conversation.
- Plan behavior changes first and keep changes small and reviewable. Do not claim checks passed unless actually run; report commands and results.
- Never commit credentials, actual confidential company information, or fabricated validation results. Use only approved providers and data.
- Do not alter the agreed scope or perform external writes without authorization. Human review remains necessary before merge and for evaluation of answer quality.
